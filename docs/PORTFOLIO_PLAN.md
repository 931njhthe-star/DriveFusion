# 포트폴리오 방향과 남은 설계 결정

> `PROJECT_OVERVIEW.md`의 기존 7번 항목을 별도로 보존한 문서다. 아래 표의 근거는 현재 구현과 향후 계획을 함께 포함한다.

| 공고의 역량 | 이 프로젝트에서 보여줄 근거 |
| --- | --- |
| C++ 응용 개발·Windows/Linux·CMake | CARLA 비종속 Core, MSVC/GCC 빌드, CTest, 설치·Replay 문서 |
| FFT·필터 등 DSP | 별도 I/Q 입력에서 주파수·잡음 조건을 통제한 C++ 알고리즘과 정량 테스트 |
| 레이더 센서 처리 | CARLA 검출점의 필터링·연관·융합과 입력 한계를 명시한 평가 |
| OpenCV·CUDA 객체 검출·트래킹 | C++에서 선정한 YOLO11n CUDA 엔진과 영상 입출력을 연결하고, 직접 작성된 `.cu`의 연산 범위를 명시하며 객체 ID 추적·오탐·ID 전환을 측정 |
| 카메라 계측·센서 융합 | 좌표·시각 보정, 거리·속도 추정, 평가용 CARLA 정답과의 오차 |
| 멀티스레드·통신·Qt | bounded queue, 버전 있는 메시지, 지연·누락 측정, Qt 검증 화면 |

이 포트폴리오는 구현·설계 역량을 보여주지만 공고의 **경력 5년이라는 기간 요건 자체를 대체하지는 않는다**. 임베디드 MCU/FPGA 연동과 실제 레이더 RF 신호 처리는 별도 장비·데이터 없이 수행한 것으로 적지 않는다.

다음 단계에서 결정할 항목은 Live 전송 형식과 Python↔C++ 경계, 샘플 I/Q 데이터의 출처, 양 플랫폼에서 빌드 가능한 YOLO11n 구성·클래스·트래커, 센서 캘리브레이션 방식, 성능 목표의 기준 장면이다. 현재 거리 오차 수치는 [거리 추정 기록](DISTANCE_ESTIMATION.md)의 단일 세션에서 측정했고, C++ 처리 성능과 독립적인 정확도 검증은 남아 있다. 선택 기능인 LLM은 기준 기능과 검증이 완료된 뒤 검토한다.
